# iLungu Club wp-admin Routing Contract

**Status:** Authoritative

## Canonical Settings Route

The iLungu Club backend Settings screen is owned by the iLungu Club top-level wp-admin menu.

- Base URL: `/wp-admin/admin.php?page=tpw-flexiclub-settings`
- Tab URL: `/wp-admin/admin.php?page=tpw-flexiclub-settings&tab={tab}`

Core Settings tabs currently include `branding`, `member-menu`, `features`, `email`, `email-logs`, `email-templates`, `email-queue`, `system-pages`, and `identity-audit`. `payment-methods` is present only when a consumer declares payments are required. Consumers may add tabs through `tpw_core_settings_tabs`; those tabs must use the same canonical base URL.

Core-owned backend navigation, actions, form return URLs, and save redirects must generate the canonical `admin.php` route. The Settings API endpoint `options.php` remains valid for forms that use WordPress Settings API submission; it is not an admin page route.

## Menu Ownership

iLungu Club Settings is visible only at **iLungu Club -> Settings**. Do not register an iLungu Club submenu beneath native WordPress **Settings** and do not use `add_options_page()` for this screen.

Existing wp-admin page slugs for Dashboard, Manage Members, Menu Permissions, System Pages, and other Club-owned screens remain stable unless a separately documented migration changes them.

## Legacy Compatibility

Legacy bookmarks or integrations may request `/wp-admin/options-general.php?page=tpw-core-settings`. Core retains a redirect-only compatibility handler to the canonical Settings route. It preserves scalar query context and retains `tab` only when that tab is currently registered.

The legacy URL is not a visible menu item and must not be generated by new Core or consumer navigation.
